1

What v5.2 actually does

v5.2 实际做什么

The pipeline is not one prompt. It is a chain that maps the paper, constructs experiment tasks, extracts focused facts, retrieves visual evidence, validates IDs and numbers, and merges records by relationships.

这不是一个提示词，而是一条完整链路：映射论文、构建实验任务、提取聚焦事实、获取视觉证据、验证 ID 与数值，并按关系合并记录。

01Ingest摄取Parse text, tables, figures and provenance.解析文本、表格、图像与来源。
02Gate AGate AMap formulations, experiments and evidence locations.映射配方、实验和证据位置。
03Task builder任务构建Issue stable experiment and candidate IDs.签发稳定的实验和候选 ID。
04Gate B + visionGate B＋视觉Extract details from focused text and selected visuals.从聚焦文本和选择性视觉中提取细节。
05Validate验证Check schemas, evidence, exact numbers and issued IDs.检查结构、证据、精确数值与已签发 ID。
06Merge合并Link formulations, arms and outcomes; quarantine uncertainty.关联配方、实验组和结果；隔离不确定项。
The core shortfall核心不足The pipeline finds many correct facts, but it does not reliably assemble all of them into complete formulation–experiment–arm–outcome records.管线能找到许多正确事实，但无法稳定地把它们组装成完整的“配方—实验—实验组—结果”记录。

Why cloning OpenAI/Codex would not solve extraction

为什么克隆 OpenAI/Codex 不能解决提取问题

This was the most important architectural misunderstanding to resolve. The open-source repository is the agent software—the carrier—not the hosted intelligence.

这是最需要澄清的架构误区。开源仓库只是代理软件和载体，并不是托管模型本身。

🚕
Downloading the taxi app does not give you a driver下载打车软件并不会给你一名司机

The repository coordinates work; the model performs the reasoning

仓库负责协调工作，模型负责推理

Cloning openai/codex into AI-LNP would provide the CLI source, tool loop and provider connections. It would not provide GPT model weights, free hosted inference, unlimited plan tokens or better scientific recall.

把 openai/codex 克隆进 AI-LNP，只会得到 CLI 源码、工具循环和模型服务连接。它不会提供 GPT 模型权重、免费托管推理、无限计划额度，也不会自动提高科学召回率。

  • Hosted Codex would still call OpenAI under the authenticated Codex plan.
  • API authentication would still use paid API inference.
  • Ollama would use a local model whose quality must be benchmarked separately.
  • A nested repository would add dependencies, upgrades and security surface without changing the scientific model.
  • 托管 Codex 仍会通过已登录的 Codex 计划调用 OpenAI。
  • API 鉴权仍然意味着付费 API 推理。
  • Ollama 使用的是本地模型，其质量必须另行验证。
  • 嵌套仓库只会增加依赖、升级和安全负担，不会改变科学推理模型。
Correct integration正确集成方式AI-LNP Python pipeline → installed codex exec → hosted Codex-plan model or a separately benchmarked local model.AI-LNP Python 管线 → 已安装的 codex exec → 托管 Codex 计划模型，或另行验证的本地模型。
3

Why the Codex audit attempts did not justify integration

为什么 Codex 审计尝试不足以支持集成

Two designs sat on opposite sides of the same context problem: too fragmented loses relationships; too large becomes expensive and difficult to validate.

两种设计处于同一个上下文问题的两端：过度切分会丢失关系；过大的上下文则成本高、难验证。

Completed · underperformed已完成 · 表现不足

The 28 evidence packets

28 个证据包

The three papers were divided into 10, 9 and 9 packets. Packets separately covered shared facts, individual experiments, unused evidence and final consistency.

三篇论文分别被拆为 10、9、9 个包，单独处理共享事实、单个实验、未使用证据和最终一致性。

40/62 → 41/62Only one exploratory requirement recovered.探索性结果仅恢复一项要求。
  • Evidence was separated from the experiment, candidate or arm that gave it meaning.
  • Unused-evidence packets often lacked the mappings needed to assign an omission safely.
  • Codex sometimes abstained because it could see useful evidence but could not prove where it belonged.
  • Scientific relationships were fragmented even though individual excerpts remained accurate.
  • 证据与赋予其意义的实验、候选项或实验组被分开。
  • 未使用证据包经常缺少安全归属所需的映射。
  • Codex 能看到有用证据，却无法证明其应归属何处，因此选择弃权。
  • 即使单个摘录准确，科学关系仍被切碎。
Stopped · not proven已停止 · 未验证

The proposed 2–4 packets per paper

每篇论文 2–4 个包的提案

The middle-ground design would keep complete experiment groups together and repeat a compact paper map. It was scientifically more sensible, but it did not reach a trustworthy completed benchmark.

中间方案会保留完整实验组，并重复紧凑论文地图。它在科学上更合理，但没有完成可信的基准验证。

Unproven—not a measured failure未验证——不是实测失败The effort was stopped before another expensive engineering cycle.在进入又一轮昂贵工程循环前被停止。
  • Larger packets reintroduced token cost and long-context attention risk.
  • True gold isolation required a separate filesystem boundary, not merely a read-only folder.
  • The validator needed field-specific semantic rules before corrections could be trusted.
  • The test was becoming another integration project instead of a quick hypothesis test.
  • 更大的包重新带来 token 成本和长上下文注意力风险。
  • 真正的金标准隔离需要独立文件系统边界，而不只是只读文件夹。
  • 验证器需要字段专用语义规则，才能信任修正结果。
  • 测试再次变成集成工程，而不是快速假设检验。
What was proven已经证明什么Codex CLI can be automated and can return structured scientific proposals. What was not proven is that the auditor improves extraction enough to justify routine use.Codex CLI 可以自动调用，也能返回结构化科学建议；但尚未证明它能把提取质量提高到值得常规使用的程度。

Why 57/62 did not mean the pipeline was already at 91.9%

为什么 57/62 不代表管线已经达到 91.9%

The earlier Codex-assisted review knew the 62 expected requirements and checked the saved evidence against them. It mainly recovered recognition and linking—not 17 newly discovered passages.

早期 Codex 辅助审查知道 62 项预期要求，并逐项检查已保存证据。它主要恢复的是识别和关联，而不是发现 17 段全新证据。

The plan now: scale the evidence base, not the audit experiment

当前计划：扩大证据库，而不是继续扩大审计实验

The product can move forward without claiming complete extraction. Missingness and uncertainty become explicit data states rather than hidden failures.

产品可以继续推进，但不宣称提取完整。缺失和不确定性将成为明确的数据状态，而不是隐藏失败。

Unknown is not different

未知不等于不同

Sparse records must not be scored as dissimilar merely because values are missing. Similarity should expose feature coverage and rely on verified dimensions.

稀疏记录不能仅因字段缺失就被判为不相似。相似度必须展示特征覆盖，并依赖已验证维度。

COMET

Train only on trustworthy arms

只用可信实验组训练

Fully verified formulation–experiment–outcome rows may enter training. Partial rows remain weak-signal or excluded; they must not be silently imputed.

只有完全验证的“配方—实验—结果”记录可进入训练。部分记录只能作为弱信号或被排除，不能静默插补。

First-class scaling metric首要扩展指标Track complete-arm percentage alongside field recall. If arm completion stays near 2/7, COMET capacity—not paper count—becomes the bottleneck.除了字段召回率，还要跟踪完整实验组比例。如果完整度长期接近 2/7，COMET 的瓶颈将是可信样本容量，而不是论文数量。

Final operating decision

最终运行决策

Use v5.2 to build a transparent evidence product—not an imaginary 100%-complete dataset

用 v5.2 构建透明的证据产品，而不是假想的 100% 完整数据集

The pipeline is useful today if the system preserves uncertainty. Codex remains an optional future investigation for genuinely poor papers, but the current audit designs should not block paper discovery, database construction or UI delivery.

只要系统保留不确定性，这条管线今天就有用。Codex 可以作为未来针对低质量提取论文的可选研究，但当前审计设计不应阻碍论文发现、数据库构建或 UI 交付。
