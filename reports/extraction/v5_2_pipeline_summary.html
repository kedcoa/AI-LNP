What changed in v5.2

  • Replaced unreliable inferred PDF headings with source-native HTML or Docling document structure.
  • Added a generalized full-paper evidence inventory and a shared paper-map contract.
  • Required exact accounting for every locally detected evidence anchor.
  • Added token-bounded experiment-context task preparation and strict evidence-ID validation.
  • Added a hidden, production-isolated NP-002 answer key and evaluator covering 245 atomic facts across 18 expected experiment arms.
  • Made arm identity sensitive to formulation, payload, dose, route, model, tissue, recipient and timepoint.
  • Removed unsafe aliases and hardened precision scoring against duplicate projections.

What worked

  • The LLM found both LNP formulations: MC3 and cKK-E12.
  • It extracted the shared components MC3/cKK-E12, cholesterol, C14PEG2000 and DSPC.
  • It recovered the 50:38.5:1.5:10 lipid molar ratio and 10:1 lipid-to-nucleic-acid mass ratio.
  • It identified QUANT DNA and Cre mRNA, liver delivery, the main models, doses and timepoints.
  • It accounted for all 60 required anchors and cited only supplied evidence IDs.
  • The paid response completed successfully and passed its structural schema.

What did not work

  • The paper-map call was a navigation stage, not a final outcome-extraction stage. It returned outcome evidence pointers rather than database-ready outcome values.
  • The LLM compressed three liver cell types into broad recipient fields instead of producing cell-specific outcome rows.
  • It collapsed the two Cre doses and retained only 0.3 mg/kg structurally; 1.0 mg/kg was mentioned only as unresolved evidence.
  • It produced four provisional contexts rather than the 18 expected formulation × payload/dose × recipient arms.
  • No numerical tdTomato percentages, DNA-copy values, fold changes or p-values were extracted.
  • The workflow stopped before the selective-vision stage, so Figures 2 and 4 were never interpreted for outcomes.

Bottom line: the call was productive as a shared metadata and evidence-mapping component, but it was not a successful end-to-end paper extraction. The strict score is 5/245 facts, or 2.0%; shared recall is 5/35 (14.3%), experiment recall is 0/210, and complete-arm recall is 0/18.

What the LLM got wrong today

  1. It optimized for the smallest schema-valid representation instead of the database granularity needed by the application.
  2. It treated several related cell-specific results as one combined context.
  3. It used an unresolved note as an escape hatch for the second Cre dose rather than creating the missing contexts.
  4. Because the first-stage schema asked for outcome_evidence_ids, not complete outcome objects, it correctly pointed to result evidence but never extracted the measurements.
  5. It could not reliably recover graph values because the call received structured HTML text, not selective figure images.

Simplified workflow going forward

The week’s work should support the application rather than turn intermediate accounting into the application. The v5.2 fast path is:

  1. Ingest the PDF/HTML and preserve source-native sections, captions and figures.
  2. Extract shared paper-level facts once: formulation, composition, ratios, payloads, doses, route and model.
  3. Locate relevant outcome paragraphs, tables and figures.
  4. Run selective vision only on relevant figures/tables, with their caption and local method context.
  5. Return outcome value, unit, comparison, significance, recipient, evidence source and an exact-versus-visually-estimated flag.
  6. Merge shared facts and outcome rows directly, validate provenance, and load the database.

For the MVP, a perfect 18-arm inventory is no longer a prerequisite for vision. Broad experiment containers may generate multiple cell-specific outcome rows downstream.
